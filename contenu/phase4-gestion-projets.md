# Phase 4 — Gestion de projets
## Gestion documentaire 2.1 — OAQ

*Printemps 2026*

---

## Contexte

Sans cadre défini, les équipes créent des canaux en double, perdent du temps à chercher des documents et ne savent pas où collaborer. Ce guide définit comment distinguer une tâche d'un projet, comment nommer un canal de projet, comment communiquer pendant les travaux et comment fermer proprement un dossier une fois terminé.

---

## Tâche ou projet ?

Avant de créer un canal dans OAQ — Projets internes, on se pose trois questions. Si les trois réponses sont OUI, c'est un projet ; sinon, c'est une tâche.

| Critère | OUI → Projet | NON → Tâche |
|---|---|---|
| 2 personnes ou plus collaborent activement ? (échanger, co-rédiger — pas juste valider ou être informé) | Plusieurs personnes impliquées | Travail en solo |
| Il y a un livrable concret ? (document, lettre, communication, décision, rapport) | Livrable identifié | Échange informel |
| Il y a plusieurs étapes à coordonner ? (rédaction → révision → approbation → diffusion) | Étapes multiples | Action unique |

Une tâche : Microsoft To Do personnel ou un message Teams direct. Un projet : un canal dans OAQ — Projets internes. **Quand on doute, on crée un canal** — le coût est presque nul, l'absence de canal coûte cher en contexte perdu.

### Exemples

| Situation | Verdict |
|---|---|
| La présidence signe et envoie une lettre de routine déjà rédigée | Tâche |
| L'équipe travaille sur un guide d'appareillage pédiatrique | Projet |
| Un employé commande des fournitures de bureau | Tâche |
| Lettre à l'Office des professions impliquant 3 départements | Projet |

---

## Nomenclature des canaux de projet

```
[CodeOAQ] — [Nom lisible]
```

Exemples : `CA — OTC prothèses 2026`, `SYN — Enquête octobre 2025`, `CFOR — Politique formation continue`, `ADM — Rapport annuel 2026`.

Pas de numérotation séquentielle. Le code du département ou de l'instance suffit pour identifier l'émetteur, et le nom lisible distingue les projets entre eux. Si deux projets risquent de porter le même nom, on précise (année, sujet, version).

---

## Communication pendant le projet

**Tout le projet vit dans le canal, jamais par courriel.** Conversations de coordination dans le canal, retours de contenu en mode révision Word/PowerPoint dans le document lui-même, réunions Teams tenues dans le canal avec compte rendu déposé dans `Réunions/[AAAA-MM-JJ]`.

---

## Registre des projets

Le registre est une liste SharePoint dans le site associé à OAQ — Projets internes, accessible via l'onglet Registre dans le canal Général.

| Colonne | Notes |
|---|---|
| Nom du projet | Nom lisible du canal |
| Responsable | Sélection dans l'annuaire OAQ |
| Statut | Non démarré / En cours / En pause / Bloqué / Annulé / Archivé |
| Lien vers le canal | URL directe vers le canal Teams |

Toutes les colonnes sont obligatoires. Tout le reste (dates, notes) vit dans le canal ou dans Teams directement.

---

## Fermeture et archivage du canal

Quand le livrable final est complété et diffusé :

1. Marquer le projet **Archivé** dans le registre
2. Archiver le canal dans Teams

Le canal devient lecture seule mais reste entièrement consultable. Tout le contexte — conversations, fichiers, décisions intermédiaires — est préservé.

---

## Revue annuelle

Une fois par année, la direction générale parcourt le registre des projets pour :

- Identifier les projets inactifs depuis plus de six mois et confirmer leur état avec le responsable
- Archiver les canaux dont le projet est terminé mais qui n'ont pas été fermés
- Vérifier que les collaborateurs externes ont encore besoin de leur accès

---

## Gestion des accès externes

Les collaborateurs externes sont ajoutés à une équipe externe dédiée, jamais à une équipe interne. Le responsable du projet les ajoute sans approbation préalable. Lors de l'archivage du projet, on retire les accès externes.
